# Kanflow「ボード」（描画ツール）計画

- 作成: 2026-11-11（GitStation セッションで作成。実装は Kanflow セッションが行う）
- 対象: Kanflow v2 開発ライン（`feat/L4-NOPBI-kanflow-v2`、`D:\APP\Kanflow-v2`）
- 状態: 2026-11-11 に利用者が「完全自作」に決定。GitStation の作業と並行して進める

## 1. 何を作るか

プロジェクトごとに何枚でも作れる、自由に描けるボード。メンバーが話しながら使う。

| 要望 | 対応 |
|---|---|
| 四角・線・矢印・文字 | 図形、線、矢印（図形につながる）、文字、付箋 |
| シートを複数（Excel のように） | ボードの下にシートのタブ。追加・名前変更・並べ替え・複製・削除 |
| Excel の表をコピペ | 貼り付けると本物の表になる（セルの文字、行・列の幅と追加・削除を直せる） |
| 写真を貼る | 貼り付け・ドラッグで画像を置く。サーバーに保存 |
| リンク | 図形や文字に URL を付ける。Kanflow の PBI・添付へのリンクも選べる |
| メンバーで会話しながら | 同時編集（ほかの人の変更が 1 秒ほどで出る）、いま見ている人の表示 |
| 簡単な報告 | ひな形（報告 1 枚、KPT、議事メモ、SWOT）、PNG / PDF で出力 |
| マインドマップ | Tab で子、Enter で兄弟を足す。自動で並ぶ |

やらないこと（v1）: 音声・ビデオ通話、Excel の数式計算、ボードの内容を AI や MCP に渡すこと。

## 2. 前提（調べたこと）

- Kanflow は Next.js 16 + React 19 + Prisma + PostgreSQL。サーバーは 1 台。
- リアルタイムは SSE（`app/src/lib/realtime/`、サーバー内のバス）。WebSocket は無い。
- ファイル保存の部品がある（`app/src/lib/upload/`: 種別の検証、ストリーム書き込み、安全なパス）。
  画像の縮小もある（`app/src/lib/image-compress.ts`）。
- 権限は 1 か所（`app/src/lib/authz/policy.ts`）。新しい操作は許可と拒否の行をテストに足す。
- CSP は `font-src 'self'`、`connect-src 'self'`。外部 CDN は使えない（社内完結）。
- 描画の部品は今は無い。Collabora（文書・表計算）は入っている。

## 3. 作り方（決定: 完全自作）

2026-11-11 に利用者が決めた。Excalidraw・tldraw・Collabora の Draw は使わない。

- 描画は **SVG + React**。文字の編集は HTML を重ねる。新しい実行時の依存は足さない
  （理由: 文字・表・リンクが DOM で素直に書ける、当たり判定が要らない、CSP を変えずに済む、
  数千個の図形までは十分に速い）。
- 図形のデータは Kanflow 独自の形（種類、位置、大きさ、文字、線のつなぎ先、版数）。
- 表は「本物の表」の図形として作る（自作なので制約が無い）。

## 4. 設計


### 4.1 データ（Prisma、新しいマイグレーション）

| テーブル | 主な列 | 役割 |
|---|---|---|
| `Board` | projectId, title, createdBy, deletedAt, sortOrder | ボード 1 枚。削除はごみ箱へ |
| `BoardSheet` | boardId, name, sortOrder, rev | シート。`rev` は変更のたびに増える番号 |
| `BoardElement` | sheetId, elementId, version, data(jsonb), deleted, rev, updatedBy | 図形 1 個 = 1 行 |
| `BoardFile` | boardId, fileId, fileName, mimeType, fileSize, uploadedBy | 貼った画像 |
| `BoardSnapshot`（P4） | sheetId, rev, data, createdBy | 履歴。前の状態に戻す |

図形を 1 行ずつ持つ理由: 2 人が別の図形を同時に直しても、互いを上書きしない。

### 4.2 API（`/api/projects/[projectId]/boards/…`）

- ボード: 一覧、作成、名前変更、削除、復元
- シート: 追加、名前変更、並べ替え、複製、削除
- 図形: `GET …/elements?since=<rev>`（差分）、`POST …/elements`（変わった図形だけ送る）
- 画像: アップロード、取得（既存の upload 部品を使う。種別検証、サイズ上限、縮小）

### 4.3 同時編集

1. ブラウザは変わった図形だけを 0.3 秒ほどまとめて POST する。
2. サーバーは図形ごとに `version` の大きい方を残して保存し、シートの `rev` を進める。
3. SSE で「このシートが rev N になった」と同じプロジェクトを見ている人に知らせる。
4. 受け取ったブラウザは `since` で差分を取り、画面に反映する。

WebSocket は足さない。今の SSE で足りる（反映は 1 秒以内が目安）。
SSE が切れたときは、今の仕組みと同じく定期取得に落ちる。

### 4.4 権限

`policy.ts` に 3 つ足す: `board.read`（メンバー）、`board.write`（編集できる役割）、
`board.manage`（削除・復元）。それぞれ許可と拒否の行を `policy.test.ts` に足す。

### 4.5 守ること

- 機密 PBI: ボード上のリンクは ID だけを持つ。題名は表示のたびに通常の API で取り、
  見えない人には出さない。
- ボードの内容は MCP、GitStation、バックグラウンドの LLM に渡さない（v1）。
- フォントと部品は自前で配る（CDN を使わない）。
- 文言は ja / en / id の 3 言語。
- 貼られたリンクは http(s) だけ許す。画像は種別を中身で確かめる。

## 5. 段階

| 段階 | 内容 | できあがり |
|---|---|---|
| B1 基盤 | テーブルと API、権限、ボード一覧、シートのタブ、キャンバス（四角・丸・線・矢印・文字・付箋、選択・移動・大きさ変更・削除、拡大縮小と移動、元に戻す、自動保存）、メニュー、3 言語 | 1 人で描いて保存できる |
| B2 貼り付け | 画像（貼り付け・ドラッグ）、リンク（URL、PBI、添付）、Excel 表の貼り付け（本物の表） | 資料を集められる |
| B3 同時編集 | 差分同期（SSE）、図形ごとの統合、見ている人の表示。2 ブラウザの E2E | 複数人で使える |
| B4 ひな形と出力 | ひな形 4 種、マインドマップの操作（Tab / Enter、自動整列）、PNG / PDF 出力 | 報告とブレストに使える |
| B5 連携 | 付箋から IceBox / PBI を作る、トークや PBI からのリンク、検索、履歴と復元 | Kanflow の一部になる |

各段階の完了条件: lint、型、テスト（DB テスト含む）が通り、レビューで CRITICAL / HIGH が無い。
作業場所: ワークツリー `D:\APP\Kanflow-board`、ブランチ `feat/L4-NOPBI-board`、試験 DB は専用（`scrum_tool_board`）。
本番（:3000）への反映は、承認を受けてから。

## 6. リスク

| リスク | 対策 |
|---|---|
| 自作なので作る量が多い | 段階ごとに使える形で区切る。B1 を小さく保つ |
| 文字の編集・矢印の接続・元に戻すの不具合 | 図形の操作を純粋な関数にして単体テストで固める |
| 大きいボードで遅くなる | 図形数の上限（例: 1 シート 5,000 個）と画像サイズ上限。見えている範囲だけ描く |
| 同時に同じ図形を直した | 後から保存した方が残る。履歴（B5）で戻せる |
| Kanflow の別セッションの作業とぶつかる | 専用のワークツリーとブランチ。v2 ラインへのマージは両方が緑のときに行う |

## 7. 既定で進めること（違えば言ってください）

1. 同時編集は 1 秒ほどで反映、見ている人の名前を出す。相手のカーソルは出さない。
2. 名前は「ボード」。全プロジェクト種別のメニューに出す。
3. ボードの内容は MCP・GitStation・バックグラウンドの LLM に渡さない。
