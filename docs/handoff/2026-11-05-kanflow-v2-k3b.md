つまずいた点（次の人のため）:

- **Kanflow の実行時は `DATABASE_URL` ではなく `DATABASE_HOST`/`PORT`/`USER`/`PASSWORD`/`NAME` を読む**（`src/lib/prisma.ts`。
  `DATABASE_URL` は Prisma の CLI だけ）。別の DB で立ち上げるときは `DATABASE_NAME` も変える。変え忘れると共有の
  `scrum_tool_v2` につながる（今回はログインに失敗しただけで、何も書いていない）。
- **Next 16 の `next dev` は `app/AGENTS.md` と `app/CLAUDE.md`（`@AGENTS.md`）を作る**。Claude Code が `app/` で読む指示が増えるので、
  `next.config.ts` に `agentRules: false` を入れる提案（小さな変更なので別ブランチで）。今回は消した。
- GitStation 側（GitStation のセッション向けの所見）: 利用者名 `admin` は予約語なので、realm の `admin` は初回のサインインで作られない
  （`bootstrap-admin --create --user gsadmin` → `admin user link-identity`）。トップレベルのグループには `admin`、マージには `merge_execute` の
  スコープが要る。この PC では `[::1]:8080` を別のプロセスが使っているので、`localhost:8080` は 127.0.0.1 に固定して開く。
